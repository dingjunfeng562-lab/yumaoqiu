# 手机摄像端 Android App（camera-android）

## 多机位版本 1.2.3

1.2.3 的自动档优先 1080p60，不支持时回落到 1080p30 等可用档位。画质设置保留各分辨率的 60 帧入口，不可用时点击显示镜头帧率、输出尺寸或编码器限制；“防频闪 60 Hz”不是“录像 60 FPS”。采集使用设备实际提供的 AE 帧率范围，排除无法达到目标帧率的输出尺寸；优先 OIS，高帧率不强开 EIS。状态栏分别显示目标、真实采集和实际发送帧率。编码降级优先保留分辨率，导播预览使用 360p 辅助层；网页 PVW/PGM/观众请求完整清晰度，避免被缩略图或播放窗口尺寸降档。60 帧最终仍取决于手机开放的能力、光线、温度和网络；尚无本机硬件实测。

1.2.2 修正导播/观众加入时的 `Object.getClass()` 空指针重连：传给 LiveKit 2.29.0 的订阅权限同时包含参与者 identity 和 SID。修正 CameraX 纹理自带旋转与 WebRTC 帧旋转叠加的问题，支持正反横屏；顶部状态与底部操作统一对齐取景框。重新扫码前保留已有凭据，新扫码成功后再替换；重新连接时创建新的采集器，避免复用已释放对象。安装包可覆盖 1.2.1，真机画面和持续连接仍需安装后确认。

后台「直播管理 → 手机扫码接入 → 配对二维码」提供直播间统一二维码，单机位和多机位均使用此入口，首次可选 1～6 个机位。二维码 30 分钟有效，有效期内在管理页和导播页重复打开均为同一码；并发扫码按事务分配空闲 CAM，满员拒绝新设备。同一手机用当前有效码重扫会恢复原机位，即使二维码曾重置或 App 清除了凭据也不会占用新机位。导播可解除配对释放机位，再让新手机扫描直播间二维码。
本 App 扫码后使用 LiveKit/WebRTC 接入；机位凭据用于断线恢复。重新生成共用码不会断开已接入的手机。手动配对支持 `live_` 和 `live_room_` 开头的码。

- 相机通过 CameraX 的同一 Session 提供本地取景和 WebRTC 视频；连续变焦、点击对焦、长按 AF/AE 锁定、曝光补偿不重建 Room。
- 只有后台选中的主音频 CAM 发布麦克风 Track；TAKE 不改变主音频。USB 音频优先路由，拔出后回退内置麦克风并上报异常。
- 沉浸式全屏，隐藏系统状态/导航栏；预览完整等比显示 16:9，超宽屏两侧留边，不放大裁切。多机位界面按手机密度设置控件尺寸，避开挖孔、隐私指示及导航区域，左右横屏自动适配；按钮不足一行时可横向滚动。
- 「画质设置」按当前镜头、分辨率对应帧时长和 H.264 编码器能力提供 720p/1080p/1440p/2160p 与帧率组合，可保存手选；多机位自动优先 1080p60，其次 1080p30。切换画质或镜头会重新接入，非支持档位自动回落。360p simulcast 层供导播缩略预览，发送码率仍受实际网络影响。
- 相机显示 ON AIR/STANDBY、电量、网络、码率、帧率、RTT、丢包和音量；前台服务保持摄像工作，重新打开界面仅重接取景渲染器。
- 观众的逐轨订阅白名单由摄像端根据服务端 Room metadata 下发给 SFU，普通观众无法持续订阅所有 CAM。

完整配置、验证记录和现场验收边界见 [多机位开发说明](../../docs/multicamera-live.md)。以下章节描述保留的 V1 单机位 RTMP/SRT 模式。

把手机变成赛场的摄像机：App 直接采集画面和声音，推流到云端地址，观众在网页上看。
不需要 OBS，不需要采集卡，直播间地址由后台下发给 App。

## 它在整套系统里的位置

```
手机 App（本目录）  ──RTMP/SRT──▶  云端推流地址
      ▲                                  │
      │ 配对码 + 配置下发（每 5 秒心跳）    ▼
  后台直播管理（/admin/broadcasts）   观众页 /live/[id]（HLS + 记分牌）
```

管理员在后台无需填写推流地址，点“生成配对码”后弹出二维码；App 扫码后由后台自动下发本房间的推流地址和拍摄参数，开始推流。
抖音只拿画面，比分由网页叠加。

## 功能

- **扫码配对**：二维码里同时带着后台地址和一次性配对码（`{"v":1,"u":地址,"t":配对码}`）。
  后台自己用的是 `localhost`，手机连不上，所以由后端给出本机的局域网地址
  （自动跳过 VMware/WSL 等虚拟网卡），正式部署可在后端 `.env` 设 `CAMERA_PUBLIC_URL`。
  扫不了码时可以“手动输入”。
- **推流**：RTMP / SRT，基于 RootEncoder，硬件编码。
- **画质自适应**：分辨率与帧率由 App 按这台手机**实测**决定，后台不设、也没有入口可改。
  App 读取摄像头的输出尺寸、曝光帧率区间和 H.264 编码器能力，只在三者都支持的
  16:9 档位（720p / 1080p / 1440p / 2160p）里挑，优先 2160p30 → 1440p30 → 1080p30，
  这些都拿不到时才退到「不低于 30 帧里最大的那档」。
  所以 4K 只能跑 24 帧的手机会自动留在 1080p30，而不是推一个明显卡的 4K。
  码率按所选档位自动匹配（720p30 约 2.6 Mbps、1080p30 约 6 Mbps、1440p30 约 12 Mbps、
  2160p30 约 24 Mbps，其它帧率按比例换算）。
  后台的「视频码率上限」只用来**压低**它：填 0 表示不限，由手机自己决定；
  场地上行带宽不够时再填一个较小的值，编码器会就低不就高。
  换镜头会重新测量：前置摄像头往往到不了 4K，档位随之下降。
- **取景框所见即所得**：预览画在居中的 16:9 取景框里，竖屏时上下留黑。
  编码输出固定 16:9，全屏预览会让操作员构出观众看不到的画面。
- **相机式操作**（变焦在传感器层面完成，编码器始终输出完整分辨率，放大不会变糊）：
  - 双指张开放大、捏合缩小，画面中央显示当前倍率；
  - 底部倍率档位（0.5 / 1 / 2 / 3 / 5 / 10，只显示这台手机支持的），点击平滑变焦；
  - 双击画面在 1× 和 2× 之间切换；
  - 单指点一下对焦，显示对焦框；
  - 红色圆形按钮开始推流，推流中变为方形，再点停止。
- **单一状态源**：配对、读取配置、预览、推流、重连都由 `SessionController` 统一管理，
  界面只负责显示它的状态，不会出现“界面显示在推、实际没推”的不一致。
- **收音**：默认优先使用外接麦克风。DJI Mic 的接收端在系统里是一个 USB 音频设备，
  App 通过 `AudioSource.setPreferredDevice()` 把它**指定**为输入设备，而不是碰运气靠系统路由。
  也可以在设置里手动锁定某个输入设备。
- **后台不断流**：推流跑在前台服务里（`camera|microphone` 类型 + 唤醒锁 + 常亮），
  锁屏或切到别的 App 都不会中断。
- **自动重连**：连接失败先让库原地重试，多次失败后按原参数重启连接。
- **参数跟随后台**：每 5 秒上报一次状态（分辨率、帧率、码率、变焦、收音设备、电量、提示）。
  后台改码率上限即时生效；改推流地址或麦克风设置会自动重连，不用碰手机。
  分辨率与帧率不在后台可改范围内，见上文「画质自适应」。

## 编译

工具链**不在**这个仓库里（工作区只放源码）。本机在 `D:\AyumaoqiuTools`：

| 组件 | 路径 |
| --- | --- |
| JDK 17 | `D:\AyumaoqiuTools\jdk17-medium` |
| Gradle 8.13 | `D:\AyumaoqiuTools\gradle\gradle-8.13` |
| Android SDK | `D:\AyumaoqiuTools\sdk`（platform 35、build-tools 35.0.0） |
| Gradle 缓存 | `D:\AyumaoqiuTools\gradle-home` |

```powershell
$env:JAVA_HOME        = "D:\AyumaoqiuTools\jdk17-medium"
$env:GRADLE_USER_HOME = "D:\AyumaoqiuTools\gradle-home"
$env:ANDROID_HOME     = "D:\AyumaoqiuTools\sdk"
cd D:\Ayumaoqiu\apps\camera-android
& "D:\AyumaoqiuTools\gradle\gradle-8.13\bin\gradle.bat" assembleDebug --no-daemon
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

安装到手机：

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

### 为什么用 `jdk17-medium` 而不是 `jdk17`

这台机器上 `D:\AyumaoqiuTools\jdk17` 里的 `java.exe` 带 **Low 完整性级别**标记（`icacls` 可见
`Mandatory Label\Low Mandatory Level`）。Windows 会阻止低完整性进程写入没有 Low 标记的目录，
于是 Gradle 连自己的原生库都解压不出来，直接报
`Could not initialize native services / Failed to load native library 'native-platform.dll'`。

`jdk17-medium` 是从原 JDK 复制出来、不带该标记的一份，Gradle 用它就正常了。仅此一处差异。

## 使用步骤

1. 后台「直播管理」里填写推流地址 → 点“生成配对码”，弹出二维码（确认上面的地址是手机能访问的）。
2. 打开 App，点“扫码配对”，对准电脑屏幕上的二维码。手机要和电脑在同一网络。
3. 插上 DJI Mic 接收端，在「设置」里确认「麦克风输入」选中了它（或保持“自动”）。
4. 双指缩放构图、点一下对焦，然后点红色按钮开始推流。
5. 推流中可以锁屏；状态栏通知里也能停止推流。后台“摄像端”卡片会实时显示状态。

## 权限说明

首次启动会申请摄像头、麦克风权限；Android 13+ 还会申请通知权限（前台服务通知需要）。
前台服务类型为 `camera|microphone`，这是 Android 14+ 后台继续使用摄像头/麦克风的必要条件。

## 已知限制

- 网页端把比分**叠加**在画面上显示；抖音拿到的是纯画面，比分不会烧进视频里。
  如果需要在抖音画面里也带比分，仍需保留原来的 OBS 合成路径。
- 手机的上行带宽是真正的瓶颈，不是 App。1080p30 建议现场 Wi-Fi 上行 ≥ 8 Mbps，
  2160p30 需要 ≥ 24 Mbps；带宽不够时在后台把「视频码率上限」调到实测上行能承受的值，
  档位不会自己降，但码率会被压住，画面会变软而不是丢帧。
- 画质只看摄像头与编码器能报出的尺寸：少数机型把 16:9 输出藏在长边非 16:9 的尺寸里
  （如 4000×3000），这类尺寸不算数，档位会低一档。设置页会显示实际选中的档位。
- 变焦低于 1×（超广角）取决于手机是否把超广角作为独立摄像头暴露出来；
  库里 `setZoom` 的下限由系统给出，低于 1× 需要切换物理镜头。
- 真机上的摄像头、DJI Mic 收音、HLS 播放和抖音推流仍需现场联调验证。
