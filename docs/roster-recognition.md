# 团体赛报名表导入（模板 / Excel / 照片 / PDF）

团体赛「批量导入团体队员」支持直接上传报名表：Excel 在浏览器本地解析，照片和 PDF 交给后台配置的识图模型识别，识别结果回填到可编辑的文本预览，管理员核对后才写入数据库。

方案的来龙去脉见 [team-roster-import-plan.md](team-roster-import-plan.md)。

## 用户流程

1. 团体赛详情 →「批量导入团体队员」（选手管理页的团体批量导入用的是同一个组件）
2. 建议先点「下载本组模板」，按模板填写
3. 拖入文件（可多选）
   - `.xlsx` / `.xls` / `.csv`：本地解析，立即出结果，不消耗 AI；CSV 自动识别 UTF-8 和 GBK 编码
   - `.jpg` / `.png` / `.webp`：逐个文件调用识图接口
   - `.pdf`：提取扫描件内嵌的页面图片后识别；文字版 PDF 见「已知限制」
4. 识别结果回填「队员数据」文本框，可逐行修改
5. 下方预览按团体分组，显示人数、来源行号和校验错误
6. 核对无误后点「导入 N 个团体、M 人」

识别结果**不会自动入库**；有错误的行会标红，导入按钮不可点。

## 本组模板与报名字段

团体赛属于某个组别，导入时按该组别的「报名字段」配置（必填 / 选填 / 不收集）生成模板并校验：

- 模板列沿用原来的 6 列：团体名称、姓名、性别、单位、联系方式、身份证号
  - 团体名称、姓名始终必填
  - 性别、身份证号按本组配置标「（必填）」或「（选填）」，设成「不收集」的列不出现
  - 单位、联系方式始终选填
- 第一行是填表说明，学号、学院、年级专业、邮箱、年龄、衣服尺寸等团体赛导入不收集的字段写在说明里，不出列
- 性别列是男/女下拉；联系方式、身份证号是文本格式，0 开头的号码和 18 位身份证号不会被 Excel 改掉
- 预览按本组配置校验：
  - 必填的性别或身份证号没填，该行报错「本组要求填写性别和身份证号」，导入按钮不可点（以前要到后端才被拒绝，而且整批失败）
  - 本组不收集身份证号却填了，提示导入时会忽略
  - 本组不收集性别时，提示这些队员抽签前都要先做资格核验
- 没有组别的旧团体赛按默认字段处理

## 解析规则

- 只有**团体名称**和**姓名**必填；其余列可留空，或按本组配置整列省略
- 同名团体自动合并为一队；Excel 里队名只写一次（合并单元格或留空）时向下沿用
- 带表头时按表头名识别列，顺序随意，可带序号列；第一行是「XX 杯报名表」这类标题时不会被当成表头
- 支持 `零一队：张三（男），第二学校，13000000` 这种紧凑写法，性别也可以写在姓名后的括号里
- 不带表头时按「团体名称、姓名、性别、单位、联系方式、身份证号」的顺序读：
  - 省略性别列（`队名，姓名，单位，电话`）或连单位一起省略（`队名，姓名，电话`）都能识别
  - 第 3 列不是性别、后面的列又对不上时（比如性别写成错字「难」，或单位后面跟的不是电话），该行报错「第 3 列「…」不是性别（男/女），后面的列对不上」，不会把单位当电话、电话当身份证号悄悄导入
  - 6 列写满时第 3 列必须是男/女或留空

## 后台配置（仅超级管理员）

位置：管理后台 →「AI 助手配置」→「报名表识别（照片 / PDF）」。

| 配置 | 说明 |
|---|---|
| 开启报名表识别 | 独立开关，默认关闭；关闭后管理员只能导入 Excel。从关闭改为开启、点保存时先弹出隐私确认（名单会发给第三方 AI 服务），确认后才保存 |
| 识别提示词 | 留空使用内置默认；「恢复默认提示词」后保存即可 |
| 上传样例测试 | 用一张真实报名表测试识别效果，不写队员。测试用的是**正在编辑**的提示词（还没保存也可以），留空 = 内置默认 |

- 卡片只对 `ROOT` 渲染，后端 `admin/roster-recognition` 也只允许 `ROOT`
- `admin/ai-config` 可以授权给普通管理员，它不返回报名表识别的开关和提示词
- 普通管理员在建队页只能拿到 `{ enabled }`，拿不到模型、提示词、Key
- 识图通道复用「图片审核」的 DeepSeek 配置（`ImageModerationConfig.apiKey` + `deepseek-flash`），不用重复填 Key；开启前必须已有 Key

## 接口

| 接口 | 用途 |
|---|---|
| `GET /api/team-competitions/:id/roster-fields` | 本组报名字段：组名，性别、身份证号是必填 / 选填 / 不收集，以及团体赛导入不收集的字段；导入弹窗用 |
| `GET /api/team-competitions/:id/roster-template` | 下载本组导入模板（.xlsx） |
| `GET /api/team-competitions/ai-recognition/status` | 建队页判断是否显示照片/PDF 入口，返回 `{ enabled }` |
| `POST /api/team-competitions/:id/teams/ai-parse` | multipart 字段 `file`，返回 `{ teams, warnings, model, elapsedMs, usage }`；每个队员带模型自评的 `confidence`（0–1） |
| `GET` / `PATCH /api/admin/roster-recognition`，`POST /api/admin/roster-recognition/test` | 超级管理员配置与试用；`test` 可带 multipart 字段 `prompt`（正在编辑的提示词） |

`team-competitions` 下的接口需要团体赛权限（`TEAMS`）；`admin/roster-recognition` 只允许 ROOT。

## 限制与超时

- 单文件 15MB；最多 200 个团体 / 500 人
- PDF 最多 6 页，超过直接提示拆分，不会悄悄只识别前几页
- 照片和 PDF 页面图片都会压缩到 2048px 以内再发送；只在内存处理，不落盘、不写日志
- PDF 多页最多 3 页同时识别，结果按页序合并；任一页失败会取消其余页的请求
- 限频（进程内计数，超出返回 429 和中文提示，失败的也算次数）：
  - 同一账号同一时间只识别一个文件
  - 同一账号 10 分钟最多 30 个文件
  - 全站同时最多 4 个文件在识别
- 超时：
  - 单次调用识图接口最多 90 秒
  - 一个文件（含 PDF 全部页）总共最多 150 秒，到点不再发起新请求
  - 前端每个文件最多等 180 秒
  - 网关先断开时（502 / 504），前端提示拆分 PDF 或裁剪图片

**线上要确认**：nginx 的 `/api/` 和 CDN 的回源超时都要大于 180 秒，否则大一点的 PDF 会被网关先断开。仓库里的 `apps/backend/nginx-photos.conf.example` 写的是 `proxy_read_timeout 300s`；线上站点配置不在仓库里，CDN 的回源超时要到 CDN 控制台查看。

## 数据与隐私

- 默认提示词明确要求**不输出身份证号、学号等证件号码**
- 图片只在内存中处理，不保存原图；识别结果不写库，必须人工核对后导入
- 请求会发送到 DeepSeek：超级管理员开启时要先确认隐私说明；管理员的导入弹窗里也写明照片和 PDF 会发给第三方 AI 服务、不希望外传请改用 Excel

## 部署

新增迁移 `apps/backend/prisma/migrations/20261110_ai_roster_recognition`：`ai_config` 增加 `roster_enabled`（默认 false）、`roster_prompt` 两列。

线上库没有 `_prisma_migrations` 表，**不要跑 `prisma migrate deploy`**。顺序：

1. `mysqldump` 备份到 `/data/db-backups`
2. 用 mysql 手动执行 `migration.sql`，再查 `information_schema` 确认两列已加上
3. 更新代码（`infra/docker/deploy.sh`）

必须先迁移再更新代码：新代码读 `ai_config` 时会查这两列，列不存在时 AI 助手配置、报名表识别都会报错。迁移只加带默认值的列，旧代码不受影响，所以先迁移是安全的。

上线后，超级管理员到「AI 助手配置」确认图片审核 Key 已配置，再开启报名表识别，用真实报名表测试并调整提示词。

## 已知限制

- 文字版 PDF（没有内嵌扫描图片）会以文件形式发给识图通道；DeepSeek 很可能不支持，这时提示改用 Excel 或截图。没有拿真实接口验证过
- PDF 扫描件要求页面图片是 DCTDecode（JPEG），或未使用预测器的 8 位 FlateDecode
- 手写、印章遮挡、反光、斜拍会降低识别率，建议先在配置页用真实报名表测试并调整提示词
- 识别结果不是最终数据：必须人工核对，尤其是姓名、性别和联系方式。预览表里有「识别把握」一列，模型自评低于 80% 的标橙
- 导入去重：姓名相同且联系方式相同（忽略空格、横线、+86）时沿用选手库已有档案，不再新建；只在当前管理员能看到的选手里找，不复用临时参赛选手；没填联系方式或性别不一致时照常新建。这个人已在本团体赛某支队里时拦下，提示重复导入
