# 自定义组别开发说明

日期：2026-11-06。

## 使用入口

后台「赛事配置」→ 对应赛事「组别设置」。可新增 U8、U18、U7-U10 等任意名称的组，设置独立项目、报名码、收费及年龄条件。已有学生组、社会组保留原报名码和数据关联。

组名不决定年龄规则。例：

| 组别名称 | 规则示例 |
| --- | --- |
| U8 | 周岁模式，选择赛事规程指定截止日，最高年龄 8，不包含上限，即未满 8 周岁 |
| U7-U10 | 周岁模式，最低 7、最高 10，包含上下限 |
| 2016 年出生组 | 出生日期范围 2016-01-01 至 2016-12-31，包含上下限 |

U7-U10 是一个独立比赛组。如需四个年龄分别抽签，请创建四个组。

新建组身份证、性别默认选填；每个字段可改为不收集、选填、必填。默认学生组、社会组保留迁移前的字段规则。已有报名后锁定资格条件与字段规则，避免使已报名选手失去资格；名称、开放状态和收费仍可修改。

## 报名与核验

- 扫码/输入报名码进入对应组别。提交时服务端重新核对报名码、组别、项目和资格。
- 提供身份证：检查 18 位格式、校验位和有效出生日期，按本组截止日或出生日期范围校验；不合龄时拒绝提交。此功能不是公安实名认证。
- 未提供身份证且有年龄限制，或未提供项目所需性别：允许提交为待核验，不能直接通过报名审核。
- 双打本人、搭档分别校验。禁止两人使用相同身份证；已填写的性别须符合男单、女单、男双、女双、混双要求。
- 后台「报名审核」→「资格核验」记录线下核验依据和性别，再通过审核。普通信息编辑保留未发生资格变更的人工核验结果。
- 后台单条录入、组别设置里的 Excel 导入、团体名单导入使用相同资格规则。团体成员可在团体详情展开队员名单后核验；待核验成员不能进入抽签或出场名单。
- 同一账号可以为不同选手报名。填报了身份证时，检查跨组及同项目重复报名。未填身份证时仍依赖姓名、联系方式及人工核验识别选手。
- 自定义组别按独立 ID 关联项目、团体赛、收费和统计，兼容字段 SCHOOL/SOCIAL 不再充当组别唯一标识。

## 数据与部署

数据库结构和回填 SQL：`apps/backend/prisma/migrations/20261106_custom_registration_groups/migration.sql`。

本机数据库已使用 `apps/backend/prisma/apply-local-age-groups.cjs` 迁移；该脚本只接受本机连接，执行前将 9 张相关表备份至工作区 `.tmp/age-group-backups`，执行后核对旧数据行数及组别关联。部署环境请按现有迁移流程备份并执行该迁移，不要直接在生产运行本机测试脚本。

后端必须配置持久的 `REGISTRATION_IDENTITY_KEY`，值为随机生成的 32 字节密钥的 64 位十六进制字符串。所有后端实例使用同一个密钥，随数据库一起妥善备份。本机 `.env` 已配置，密钥未加入版本控制；生产环境需单独配置。密钥缺失时身份证提交会返回服务配置错误，不会降级为明文存储。更换密钥需要配套数据迁移。

完整身份证使用 AES-256-GCM 加密保存；查重使用带密钥指纹。API 全局过滤密文及查重指纹，仅在授权报名详情返回脱敏号码和出生日期。现有公共名单和导出不新增完整身份证字段。

部署顺序：备份与数据库迁移 → 配置密钥 → 生成 Prisma Client → 构建前后端 → 重启应用。此次开发未部署到线上。
