# 组别场地分配、人工调场与大屏同步

## 使用入口

后台「场地自动排程」：

1. 「组别场地与日期」（原「组别场地分配」）按报名组别选择不限制或指定场地，支持搜索、批量设置。指定模式至少选择一片启用场地；多个组别可以错时共用。
2. 展开组别可把场地精确到**单项**（男子单打、女子单打、男子双打、女子双打、混合双打）：单项规则为「继承组别」「不限制」「指定场地」。默认继承组别，旧赛事行为不变；「不限制」表示忽略组别限制、使用全部启用场地。
3. 同一弹窗的「比赛日期」按**组别**设置本组在哪几天比赛：从赛事开始到结束的每一天里选一天或几天，不选为不限；可勾选多个组别批量设置。只能选赛事日期内的日子；赛事日期改过后不在范围内的旧日子标红，重新选择后才能保存。比赛日期只到组别，不细分到单项；团体赛按所属组别。
4. 「自动排程」先预览各组已排、未排、预计结束时间及具体比赛，再应用。预览按组别汇总（含比赛日期），展开可按单项查看；预览不写入赛程，也不通知大屏。应用时如果规则、比赛状态或场地已变化，要求重新预览。
5. 赛程表「调整」支持手动换场、调整时间、检查冲突、查找所选场地最近可用时间。默认人工固定；范围外场地或组别日期以外的日子需明确勾选（临时借场 / 临时改期）。团体对阵联动全部未开始子项；已开赛后保持同一场地。
6. 「解锁」取消人工固定；团体赛同时取消本对阵全部未开始子项的固定。重新排程和清空排程默认保留人工固定；清空时可显式选择包括人工固定。
7. 「调整记录」显示最近 50 次组别规则、自动排程、人工调整和清空操作的前后记录及操作人。

规则保存本身不移动现有比赛；不符合新规则的待赛场次标记为需调整（场地不符标「需调场」，日期不符标「需改期」）。组别规则通过 `TournamentGroup.id` 关联，兼容自定义组别和团体赛。抽签 A/B 小组不单独配置。

## 排程约束

- 自动排程使用赛事启用场地、本次选择场地、**生效场地范围**的交集，不自动借用范围外场地。生效范围按「单项优先、组别兜底」计算：单项设置了指定场地或「不限制」时以单项为准，否则沿用组别；团体赛对阵没有单项行，始终按组别规则。空交集、时段不足及前置比赛未排入均返回具体未排原因（单项规则的提示会指名男子单打等单项）。
- 全赛事统一检查场地、参赛者占用；按轮次依赖排程。同等轮次与项目优先级下优先选择场地较少的比赛。
- 组别比赛日期：自动排程只把本组比赛排在选中的日子（每日起止时间、休息时段照旧），日期限制越紧的组别越先排；排不下的留待排程并写明「某组的比赛日期（11月15日）内已无空位」；选的日子都不在赛事日期内时提示重新设置。「查找最近可用时间」也只在组别日期里找。
- 人工调场与对局管理、团体编排入口共用后端校验。改到组别日期以外的另一天，要勾选「允许本场临时超出组别规则（范围外场地或日期）」，比赛记为「临时改期」（`Match.dateOverride`）；日子不变只改场地、时长或当天时间，不需要确认。人工例外仅放宽组别场地范围和比赛日期，不绕过场地/选手重叠、时间窗口、赛事日期或前置比赛约束。
- 自动排程默认沿用比赛预估时长，可显式统一覆盖未固定比赛。保存本次每日时间窗口、休息时段和场间间隔，供人工调整校验使用。
- 最近可用时间查询只返回建议，不写入；团体对阵按保留的子项间隔寻找连续时段，连续时段不足时明确提示管理员调整。
- 进行中、已完成、已实际开赛的比赛不会被人工调场、自动排程或清空移动。
- 事务按赛事串行化，写入检查比赛状态。预览指纹防止应用过时安排；事务失败不广播。

## 大屏与各端同步

排程事务提交后通过现有 `/scores` Socket.IO namespace 广播 `bracket:update`，携带赛事 ID。复用 `ScoringGateway` 的缓存失效机制，在通知客户端之前清理公开签表/团体看板缓存。

- 赛事场地大屏、公共大屏、公开签表、裁判场地列表、后台赛程订阅后重新拉取该赛事。
- 裁判记分页接收对应赛事的结构变更后后台刷新。
- 同一批排程只在提交后通知，保留各端已有断线重连和定时刷新兜底。
- 保存组别规则及预览不广播，因为比赛落位尚未改变。

## 数据与部署

新增 `TournamentGroup.restrictVenues`、`GroupVenue` 关联表、`Event.venueRule`、`EventVenue` 关联表、`Match.scheduleLocked/scheduleOverride/unscheduledReason`、`Tournament.schedulingSettings`、`ScheduleOperationLog`，以及 `TournamentGroup.playDates`（组别比赛日期，`["2026-11-15", ...]`，为空不限）、`Match.dateOverride`（临时改期）。

数据库迁移：`apps/backend/prisma/migrations/20261106_group_venue_scheduling/migration.sql`、`apps/backend/prisma/migrations/20261108_event_venue_rules/migration.sql` 与 `apps/backend/prisma/migrations/20261113_group_play_dates/migration.sql`。`Event.venueRule` 默认 `INHERIT`，存量赛事继续沿用组别规则；`playDates` 为空即不限日期，新字段默认保持旧赛程可继续使用。部署时先按环境既有流程应用迁移并生成 Prisma Client，再启动新版后端。

本机增量迁移脚本 `prisma/apply-local-group-venues.cjs`、`prisma/apply-local-event-venues.cjs` 只允许连接本地地址，先备份原表定义及比赛排程至工作区 `.tmp/*-backups`；发现部分迁移会停止，完成后核对原比赛/单项行数。不会改动已有比赛落位。
