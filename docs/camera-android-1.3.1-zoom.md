# 1.3.1 原生变焦响应修复

用户反馈：红米 K60 Pro，本机取景画面缩放不流畅，不如上一版本。Android 版本未提供。

## 代码中确认的问题

1. 1.3.0 的 `ZoomRequestState` 将目标拆成多次小步；`ZoomController` 每一步都等待 CameraX Future 完成才发送下一步。这个回调等待的是相机重复请求结果，不是一个显示帧，导致手势目标与画面变焦之间产生额外追赶延迟。
2. 每一步倍率变化都会复制整份 `LiveCameraUi` 并触发完整 `render()`，反复设置状态、音频、提示和其他控件。
3. 1.3.0 把自动优先档从 1080p60 改为 1080p30；同一 CameraX 会话驱动本地取景与视频发布，因此本地取景也受到帧率选择影响。

这些是代码层面确认的响应退化点；尚未对用户手机采集帧时间或 GPU trace，不能据此证明所有机型上的卡顿均已消除。

## 本次改动

- 手势、滑条每个显示帧合并到一个最新目标，直接调用 `CameraControl.setZoomRatio`；下一帧不等待上一请求的硬件完成回调。
- 使用原生相机的变焦能力和范围；不对 SurfaceViewRenderer 做缩放，不创建新相机 Session、Track 或编码器。
- 旧缩放请求被新请求替代时忽略正常取消；过期镜头/请求回调不会改变当前倍率状态或弹出假错误。
- 取消双指灵敏度的额外 0.65 阻尼，按手指比例直接累积并限制到镜头范围；到达最大倍率后反向捏合立即响应。
- 按钮采用固定 240 ms 的倍率过渡，按帧时间计算当前位置；帧延迟时直接到当前时间应有的位置，不补播旧步进。手势可立即中断按钮过渡。
- 倍率采用独立状态流，只更新倍率文字和滑条；文字和滑条值未变化时不重复设置。
- 滑条从 100 级提升到 1000 级；双指操作后禁止误判单击对焦，避免松开一根手指后触发焦点搜索。
- 旧 RTMP/SRT 模式使用同样的直接手势/定时按钮策略，停止相机时清除待执行的变焦帧。
- 自动档恢复优先 1080p60，能力不足时诚实回落；保留用户手选档位和现有码率设置。
- 增加左下角常驻「当前摄像头为主视角」提示，位于操作栏上方，随栏高和横屏布局定位。服务端 `activeCameraId` 等于本机且正在接入时显示；导播切走/停止接入隐藏，PVW 选择不触发。按 PGM 选择而非直播公开开关判断，顶部 ON AIR 仍单独表示正在直播。提示不进入编码视频。

这一调整按用户最新的「原生、跟手、流畅」要求执行，替代 V1 初始实施中严格等每次 Future 完成的做法。CameraX 本身管理原生最新缩放请求的替换；应用层不保留逐步追赶队列。

## 使用

覆盖安装 `outputs/camera-android/Ayumaoqiu-Camera-1.3.1-debug.apk`，无需卸载。进入「画质设置」选择「自动（优先 1080p · 60 帧）」。若以前手动选过 30 帧，该设置会继续保留，需要手动切回自动。

在红米 K60 Pro 上先观察本机取景，连续慢速/快速捏合、反向捏合、滑条拖动，再测试按钮过渡中插入捏合。分别测试未接入和正在接入时的手感；同时查看「采集 FPS」，不要仅看「目标 FPS」。拍摄画面、镜头可用范围和物理镜头融合仍由手机相机 API 决定。

软件回归验证覆盖目标合并、不等硬件确认即可提交下一帧、不同刷新率下按钮时长一致、卡帧后无追赶尾巴、手势抢占按钮、倍率边界反向和无效输入。测试结果与安装包校验信息见 `outputs/camera-android/verification-1.3.1.json`。

最终完整构建成功，65 项单测全部通过；lint 0 errors、80 warnings。带主视角提示的最终 APK 签名验证通过，证书与 1.3.0 一致，versionCode 从 7 增至 8，可覆盖安装。SHA-256：`C968026B6C3244A98ECF9C68EC90B63D9E39A6C7C381B70EAF42AA42B1582894`。提示显隐由 PGM 状态直接驱动，未执行真实导播切换/手机界面的端到端验收。

未连接或安装到用户红米 K60 Pro，实际无卡顿效果仍需该机复测。

API 依据：[CameraControl.setZoomRatio](https://developer.android.com/reference/androidx/camera/core/CameraControl#setZoomRatio(float)) 说明 Future 在相机请求结果包含目标倍率后完成，新倍率会使旧请求取消；因此其完成时间不适合作为手势调度节拍。
