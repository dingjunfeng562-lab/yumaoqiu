# 比赛签到与观众对阵页

## 入口

- 后台：`/nicaiyixiahh/check-in`，菜单名称「赛事签到」。
- 观众：`/match-check-in/:tournamentId`，后台「观众页面」按钮打开。页面顶部只显示品牌与赛事名称。
- 后台可使用 `?tournamentId=...` 预选赛事。

## 行为

- 按中国时区（Asia/Shanghai）归入比赛日期；默认优先今天，无今日赛程时显示最近的比赛日。
- 每个场地一列，场次按时间排列。卡片大小支持 50%–125%，偏好保存在浏览器中。
- 所有日期可在同一页面分组查看，使用一个纵向滚动区域。未排时间、未分场地的比赛单独保留展示。
- 普通电脑上六个场地同时可见；场地较多或屏幕较窄时保留横向滚动，避免压缩到无法辨认。
- 观众页只读；后台点击卡片打开签到抽屉，支持单方、双方签到和确认后撤销。
- 签到抽屉提供「弃权处理」：选择甲方、乙方或双方，可填写原因，核实结果后确认。仅持有 `SCORING` 权限（或 ROOT）的账号可操作，签到页只处理尚未开赛且双方阵容完整的比赛；开赛后的弃权在裁判端处理。复用真实裁判弃权接口，单方弃权判对方获胜，双方弃权作废本场并显示红色「双方弃权」。结果同步到观众页、裁判端及后续晋级，不能在签到页撤销。
- 灰色未签到、橙色单方签到、黄色双方到齐、绿色比赛中、紫色结束、红色弃权。状态始终带文字。
- 开赛与结果沿用裁判端数据，签到不会自动开赛；开赛、结束、取消和弃权后均禁止修改签到。
- 双打整方签到表示两名运动员均到场。签到按场次保存，不传递至同一选手的其他比赛。
- 选手身份指纹包含参赛方 ID 和双方人员 ID，换人后原签到失效；旧抽屉请求返回 409。
- Socket.IO `/scores` 的 `check-in:update`、`scoreboard:update`、`bracket:update` 触发刷新，另有 15 秒轮询和回到页面时刷新。读取 12 秒超时，网络错误时保留旧数据、明确提示并暂停操作。
- 刷新节流：后台签到页收到任何推送 0.6 秒内刷新。观众页的 `scoreboard:update`（每得一分一次）最多 5 秒刷新一次，`check-in:update`、`bracket:update` 仍 0.6 秒内刷新；线上出口带宽只有约 20 Mbps，观众多时不能每分都拉全量。
- 公开接口 `/public/tournaments/:id/check-in` 按赛事缓存（同一数据版本最多 3 秒，最多 100 个赛事），计分、晋级广播前（`ScoringGateway.publicDataChanges`）和签到写入后立即失效。后台接口不缓存。
- 公开接口不返回选手指纹 `key`，只有后台接口返回（签到、弃权时核对对阵）。
- 兼容旧浏览器：不用 `AbortSignal.any` / `AbortSignal.timeout`、`Array.prototype.at`（iOS 17.4 以前的 Safari、微信没有），`dvh` 前有 `vh` 兜底。

## 权限与持久化

- 后台复用 `SCHEDULING` 或 `SCORING` 功能权限。ROOT 可管理全部赛事，其他账号限定自己提交的赛事。
- 公开接口只读取已批准、已发布、未归档赛事，以及已发布的单项对阵或团体赛，不返回操作人、联系方式等后台信息。
- `MatchCheckIn` 以 `(matchId, side)` 为主键，存签到时间、人员指纹及操作人；`MatchCheckInLog` 记录签到和撤销。
- 写入事务先锁定 Match 行，再读取状态和处理目标方；重复签到不重写时间和日志。
- `PUT /api/check-in/matches/:matchId` 参数：`side` 为 `"1" | "2" | "both"`，`checked` 为布尔值，`side1Key` 和 `side2Key` 为读取时返回的人员指纹。

## 部署

迁移 `apps/backend/prisma/migrations/20261109_match_check_in/migration.sql` 只新建 `MatchCheckIn`、`MatchCheckInLog` 两张表，不改旧表，旧版本代码不受影响，回滚安全。
线上数据库没有 `_prisma_migrations` 表，不要用 `prisma migrate deploy`：先确认两张表不存在、备份数据库，再用 mysql 手动执行这个文件，然后构建和重启后端、前端。

不要在迁移完成前启动新版后端，因为读取赛程需要新增的签到表。
